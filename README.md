## Architecture
Voice input -> Sarvam STT -> Query translation (if non-Hindi) -> Chunking + Retrieval (ChromaDB, multilingual embeddings) -> Gemini generation -> Guardrails (unsafe input, off-topic, grounding check) -> Answer

## Tech stack

- **Speech-to-text:** Sarvam AI
- **Embeddings:** sentence-transformers (paraphrase-multilingual-MiniLM-L12-v2)
- **Vector DB:** ChromaDB
- **Generation:** Google Gemini (gemini-3.5-flash-lite)
- **Backend:** FastAPI
- **Frontend:** Vanilla JS + HTML/CSS (deployed separately, see frontend repo)

## Chunking strategies compared

We implemented and evaluated 3 chunking strategies on the MSMARCO-XI (Hindi) dataset:
- Fixed-size with overlap
- Fixed-size without overlap
- Sentence-aware (splits at sentence boundaries)

See `compare_chunking.py` for the comparison script and results.

## Guardrails

- Unsafe input keyword filtering
- Off-topic detection via retrieval distance thresholding
- Grounding check comparing generated answer against retrieved context

## Known limitations

- Backend requires ~1GB+ RAM (multilingual embedding model + torch), which exceeds free-tier limits on Render/Railway/HF Spaces. For this submission, the backend runs locally and is exposed via ngrok.
- Off-topic detection is a coarse distance-based filter; grounding check is a word-overlap heuristic, not a second LLM-based judgment call.
